# VoltGuard AI (R0 prototype)

VoltGuard turns a transformer energy-gap alert into a ranked, explained list of the premises
most likely responsible, then supports inspection, reporting and model learning. Team F-35,
Hackspire Lumina, Domain 1. Requirements: `VoltGuard_SRS.md`; design: `VoltGuard_SDD.md`.

**R0 runs on simulated data and fake personal details only.**

> Status: the build is in progress. `HANDOFF.md` lists what works today and what is next.

## Quick start (Windows laptop)

1. Install Docker Desktop (WSL 2 backend). Move its disk image to D:
   (Docker Desktop -> Settings -> Resources -> Advanced -> Disk image location).
2. Give WSL 2 enough memory: create `%UserProfile%\.wslconfig` with

   ```
   [wsl2]
   memory=12GB   # on a 16 GB laptop; leave ~4 GB for Windows
   swap=8GB
   ```

   then run `wsl --shutdown` and restart Docker Desktop. With 8 GB RAM use the small model
   (`LLM_MODEL=phi3.5`) or `LLM_MODE=mock`.
3. In PowerShell, from the repository folder:

   ```powershell
   .\make.ps1 demo      # setup, build, database, seed, detection run, printed demo steps
   ```

   Open http://localhost:8080. `.\make.ps1 help` lists every target. The same targets exist
   in the `Makefile` for Git Bash, WSL or Linux.

All bulky files live under `DATA_ROOT` (default `D:/VoltGuard`): datasets, uploads, photos,
PDFs, logs, the audit anchor and models. The database sits in a named Docker volume inside
Docker's disk image, which is on D: after step 1.

## Data modes

The detection pipeline reads only the canonical tables (`backend/voltguard/data/canonical.py`).
`config/data_sources.yaml` picks the source per table; switching is a config change plus
`make.ps1 pipeline`.

| Mode | What it uses | Needs |
| --- | --- | --- |
| Offline (default) | Built-in synthetic tropical household profiles; pattern model trained on synthetic SGCC-style windows | Nothing to download |
| Public datasets | London smart-meter profiles, SGCC theft data, data.gov.my consumption | `make.ps1 fetch` (Kaggle API key for SGCC/London) |
| Uploads | Your own files in `DATA_ROOT/uploads/<dataset>/` or the Data manager page | See `data/uploads/README.md` |

Voltages are generated by the load-flow model, because the open datasets hold kWh only, so
R0 shows that the voltage locator works on physics-consistent data, not on TNB meters (SRS AS-3).

## Development without Docker

```bash
python3 -m venv .venv && .venv/bin/pip install -r backend/requirements.txt
cd backend
../.venv/bin/python -m voltguard train-models   # pattern model + autoencoder (under a minute)
../.venv/bin/python -m pytest                    # tests are named after SRS IDs
../.venv/bin/python -m voltguard simulate --run demo && ../.venv/bin/python -m voltguard detect
```
